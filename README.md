# خادم صحنك (Sahnak Server)

خادم Node.js حقيقي لمنصة "صحنك" — حسابات مستخدمين فعلية (بريد إلكتروني أو رقم هاتف + كلمة مرور)،
رمز تحقق يُرسل فعليًا عبر البريد الإلكتروني (SMTP) أو الرسائل النصية (Twilio)، وقاعدة بيانات فعلية
على الخادم (ملف `db.json`)، ولوحة إدارة منيو محمية بجلسة دخول حقيقية (JWT).

## 1. التثبيت

```bash
cd sahnak-server
npm install
cp .env.example .env
```

افتح `.env` واملأ القيم:
- `JWT_SECRET`: أي نص عشوائي طويل.
- بيانات SMTP لإرسال رمز التحقق عبر البريد (مثال: Gmail App Password، أو Mailtrap للتجربة، أو أي مزود SMTP).
- بيانات Twilio لإرسال رمز التحقق عبر SMS (اختياري).

> إن تركت SMTP أو Twilio فارغين، سيعمل الخادم في **وضع تجريبي**: يطبع الرمز في الطرفية بدل إرساله فعليًا،
> حتى تتمكن من تجربة النظام بالكامل قبل ربط بيانات إرسال حقيقية.

## 2. التشغيل

```bash
npm start
```

سيعمل الخادم على `http://localhost:3000`.

- `/` الصفحة الرئيسية
- `/auth.html` إنشاء حساب أو تسجيل الدخول
- `/dashboard.html` **الصفحة الخاصة بحساب المستخدم** (محمية — يُعاد توجيه أي زائر غير مسجّل دخول إلى صفحة الدخول تلقائيًا)
- `/menu.html?slug=xxx` صفحة المنيو العامة لأي مطعم منشور

## 3. كيف يعمل تدفق التحقق

1. يدخل المستخدم بريده الإلكتروني أو رقم هاتفه + كلمة مرور في `/auth.html`.
2. يرسل الخادم رمز تحقق مكوّن من 6 أرقام فعليًا عبر SMTP (بريد) أو Twilio (SMS) حسب الاختيار.
3. بعد إدخال الرمز الصحيح، يُنشئ الخادم الحساب فعليًا في `db.json` ويصدر جلسة دخول (JWT) في كوكيز آمنة.
4. يُعاد توجيه المستخدم تلقائيًا إلى `/dashboard.html` — صفحته الخاصة، حيث يدير مطعمه ومنيو الخاص به فقط.

## 4. النشر على استضافة حقيقية (Production)

هذا الخادم جاهز للنشر على أي استضافة تدعم Node.js، مثل:
- **Render** أو **Railway**: اربط المستودع، وأضف متغيرات البيئة من `.env` في لوحة الاستضافة.
- **VPS خاص** (DigitalOcean, Hetzner...): شغّله عبر `pm2 start server.js` خلف Nginx.

## 5. استعادة كلمة المرور

من `/auth.html` تبويب "تسجيل الدخول" → "نسيت كلمة المرور؟" → يُدخل المستخدم بريده أو رقم هاتفه:
- **حساب مسجّل ببريد إلكتروني**: يُرسل رابط الاستعادة إلى نفس البريد مباشرة.
- **حساب مسجّل برقم هاتف**: يطلب الموقع من المستخدم إدخال بريد إلكتروني لأول مرة (يُحفظ في حسابه كـ`recoveryEmail` للمرات القادمة)، ثم يُرسل رابط الاستعادة إليه.

الرابط صالح لمدة 30 دقيقة، ويُطبع في سجلات الخادم (Logs) إن لم يكن SMTP مُعدًّا بعد. المستخدم يفتح الرابط على `/reset-password.html` ويضع كلمة مرور جديدة.

## 6. الدفع (تحويل يدوي + موافقة يدوية)

بما أن بوابات الدفع الإلكتروني في تونس (Flouci، Konnect، إلخ) تتطلب تسجيلاً تجاريًا (حتى لو بسيطًا) لتفعيل الدفع الأوتوماتيكي عبر API، يعمل النظام حاليًا بطريقة **تحويل يدوي مؤكّد يدويًا من صاحب الموقع** — لا يحتاج أي تسجيل تجاري:

1. اضبط `PAYMENT_PHONE` في `.env` برقم هاتفك المرتبط بحسابك الشخصي في Flouci (أو `PAYMENT_RIB` لحسابك البنكي)
2. اضبط `ADMIN_PASSWORD` بكلمة مرور قوية خاصة بك — هذه بوابتك الوحيدة لمراجعة الاشتراكات
3. عند اشتراك أي مستخدم: يرى رقمك ويحوّل يدويًا، ثم يضغط "لقد قمت بالتحويل"
4. تفتح أنت `/admin-payments.html`، تسجّل الدخول بكلمة مرور المشرف، وتراجع طلبات الاشتراك المعلّقة
5. بعد التأكد من استلام التحويل فعليًا (تحقق من تطبيق Flouci أو حسابك البنكي)، اضغط "قبول" — يُفعَّل حساب المستخدم فورًا

**تدفق الاشتراك:** المستخدم يسجّل الدخول → إن لم يكن مشتركًا يُوجَّه إلى `/billing.html` → يرى رقمك ويحوّل يدويًا → يضغط "لقد قمت بالتحويل" → تنتظر طلبه في `/admin-payments.html` → تقبله بعد التأكد من التحويل → يُفعَّل حسابه تلقائيًا.

> **الترقية لاحقًا:** إذا حصلت على "patente de personne physique" (رخصة مهني بسيطة)، يمكنك فتح حساب Flouci Gateway المهني وربط دفع أوتوماتيكي كامل بدل المراجعة اليدوية — هذا يتطلب إعادة إضافة تكامل API، وأنا جاهز لمساعدتك في ذلك وقتها.
